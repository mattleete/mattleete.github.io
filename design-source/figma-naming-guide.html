Portfolio Design System — Figma Guide

Auto-Layout Naming

How to name every frame in Figma so that the designs translate cleanly into code. Organised by Atomic Design level — from the smallest element up to a full page.

Level 01

Atoms

The smallest possible element. Cannot be broken down further. These are the raw ingredients — a single button, a tag, a link, a label. When they have auto-layout (e.g. a tag with padding), name them by what they are.

Examples from this portfolio
tag
button-primary
button-secondary
button-text
nav-link
eyebrow
divider
image-placeholder
avatar-placeholder
Rules
1
What it is, not what it looks like. Not blue-rectangle or rounded-pill — those describe appearance. tag describes meaning.
2
Singular, lowercase, hyphenated. nav-link not Nav Links or navlink.
3
Atoms don't always need auto-layout. A standalone text layer named eyebrow is still an atom — the name is what matters here, not the frame type.
Level 02

Molecules

A small group of atoms that does one job together. This is the first level where auto-layout becomes essential — every molecule must be an auto-layout frame. A molecule is a unit you would describe in two words: what it is and what it contains.

Examples from this portfolio
card-footer → tags + arrow · horizontal
card-meta → eyebrow + title + desc · vertical
nav-actions → nav-link × 3 + button · horizontal
hero-actions → button-primary + button-text · horizontal
section-header → heading + section-link · space-between
stat-item → stat-number + stat-label · vertical
phase-item → phase-num + phase-content · horizontal
concept-header → concept-title + priority-tag · horizontal
discipline-item → discipline-name + meta · space-between
Rules
1
Always auto-layout. If it groups two or more atoms, it must be an auto-layout frame with explicit direction, gap, and padding set.
2
Name by what it does, not what it looks like. card-meta not text-stack-left.
3
A molecule only does one job. If you find yourself naming it header-and-description-and-tags-and-button, it's an organism, not a molecule.
4
Set the spacing in Figma, not by eye. The gap value in auto-layout becomes gap in CSS. Use the spacing scale tokens: 4, 8, 16, 32, 64px.
Level 03

Organisms

A complete, self-contained UI section. An organism is the main building block of a page — it could be dropped onto any page and would make sense in isolation. Every organism must be a Figma component.

Examples from this portfolio
nav → logo + nav-actions · full width
hero → hero-left + hero-right · grid
project-card → card-image + card-body
cards-grid → 3× project-card · horizontal
stats-strip → 3× stat-item · equal columns
about-strip → about-left + discipline-list
case-study-hero → breadcrumb + title + meta-grid
journey-map → 3× journey-cell · horizontal
concepts-grid → 6× concept-cell · 2-column
footer → footer-name + footer-links
Rules
1
Make it a Figma component. Press ⌥⌘K. Every organism should be a component so that edits propagate to all instances across pages.
2
Name it what you'd call it out loud. Not section-3. If you'd say "the cards grid" in a meeting, name it cards-grid.
3
Full-width organisms span 1440px and use horizontal padding internally (64px on this system). Never use margin to push content in — use padding on the organism frame itself.
4
Variants for states. If an organism has a hover or active state (e.g. project-card), add it as a variant — not a separate frame.
Level 04

Templates

A full-page layout — the skeleton. A template is a vertical auto-layout frame at 1440px wide that stacks organisms in order. Think of it as the table of contents for a page. Templates contain placeholder content, not real copy.

Naming
template-home
template-about
template-case-study
template-contact
Layer structure example — template-home
template-home
└── nav
└── hero
└── cards-grid
└── stats-strip
└── about-strip
└── footer
Rules
1
Vertical auto-layout, gap = 0. Spacing between sections is handled by each organism's internal padding — the template frame itself has no gap.
2
Width = 1440px, height = hug. Never set a fixed height on a template frame — it should grow with its content.
3
Organisms only — no raw atoms or molecules at this level. If you're placing a text layer directly inside a template, it belongs in an organism first.
4
One template per page type. The case study template is reused for both Spix and Rest Super — only the content changes, not the structure.
Level 05

Pages

A template filled with real content. The distinction from a template is content, not structure. In Figma, a page is simply your template renamed to reflect the specific instance — particularly useful when one template is used for multiple pages.

Naming
page-home
page-about
page-case-study-spix
page-case-study-rest-super
page-contact
Full layer structure example — page-case-study-rest-super
page-case-study-rest-super
└── nav
└── case-study-hero
└── breadcrumb
└── hero-inner
└── cs-title
└── meta-grid
└── hero-image
└── overview-strip
└── cs-section (× 8)
└── concepts-grid
└── next-project-strip
└── footer
Rules
1
Real content only. Replace every placeholder with actual copy, images, and data before handing back for development.
2
Don't break the template structure. If you need a new section that doesn't exist in the template, add it as a new organism — don't patch it in with ungrouped layers.
3
Image layers named for export. Name every image layer with a descriptive export name: thumbnail-rest-super, photo-matt. This becomes the filename.

The one rule
"If you can describe what it is in two words, that's the name." — Every layer name becomes a CSS class or component name in code. Name it what a developer would call it.
