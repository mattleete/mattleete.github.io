Portfolio Design System — v1
Usage Guidelines
This document defines how and where to use each element of the design system. Following these guidelines keeps the portfolio consistent, legible, and intentional across every page and state.
01 — Colour Usage
Text colours
Token
Use for
Avoid
Colour/Text/Primary
#0a0a0a
Page titles, headings, body copy, labels, navigation, all default readable text.
Decorative or secondary information — risks flattening the visual hierarchy.
Colour/Text/Secondary
#4a4a4a
Supporting text, descriptions, subheadings, card body copy, metadata.
Primary actions or anything requiring immediate attention.
Colour/Text/Tertiary
#8a8a8a
Eyebrows, captions, timestamps, placeholder text, style annotation labels.
Body copy or anything longer than a few words — fails WCAG AA at small sizes.
Colour/Text/Disabled
#d0d0d0
Disabled states only — conveys unavailability. Style annotation meta on white backgrounds.
Any active or interactive text.
Surface colours
Token
Use for
Avoid
Colour/Surface/Page
#ffffff
The main page background. Every page starts here.
Cards or raised elements — creates no separation from the page.
Colour/Surface/Subtle
#f7f7f7
Image placeholders, code blocks, input backgrounds, alternating row tints, section dividers.
Large background areas — the difference from white is too subtle for sections.
Colour/Surface/Raised
#ffffff
Cards and overlays. Elevation is indicated by border, not fill — this token pairs with Colour/Border/Default.
Using without a border — it will be invisible against the page surface.
Border & Accent colours
Token
Use for
Avoid
Colour/Border/Default
#ebebeb
Card borders, dividers, input outlines, table row separators. The default resting state for all bordered elements.
Hover or focus states — too subtle to communicate change.
Colour/Border/Strong
#d0d0d0
Hover states on bordered components (secondary button hover, card hover), focus rings, active inputs.
Default resting states — over-emphasises inactive elements.
Colour/Accent/Default
#1a56ff
Primary CTA buttons, accent tags, active link underlines, focus indicators. One prominent accent per view.
Decorative backgrounds, large fills, or more than one prominent use per screen.
Colour/Accent/Hover
#0040e0
Hover state of primary button only. Never used as a static colour.
Any static usage — this token only communicates interactivity change.
Do
Use Primary text for headings and body copy, Secondary for supporting descriptions, Tertiary for metadata and eyebrows.
Pair Surface/Raised with Border/Default to create cards that sit above the page.
Reserve Accent/Default for a single prominent action per view.
Don't
Don't use Tertiary text for body copy — it fails contrast requirements at 14px.
Don't use Accent/Default for backgrounds, illustrations, or decorative fills.
Don't mix Border/Default and Border/Strong on the same component in its resting state.
02 — Typography Usage
Visual hierarchy
1
Type/Display — 72px / 600
Portfolio
Hero section headline only. One instance per page maximum. Never use for subheadings or section titles.
2
Type/Heading-1 — 40px / 600
Selected Work
Primary page sections and case study titles. One per logical section. Introduces a major content area.
3
Type/Heading-2 — 24px / 600
About the Project
Subsection headings within a page section. Modal and drawer titles. Card group headers.
4
Type/Heading-3 — 16px / 600
Project Title
Card titles, list item headings, sidebar section titles, inline content labels.
5
Type/Body — 14px / 400
The default reading size for all long-form content.
Paragraphs, case study body copy, about section text, any prose longer than two sentences.
6
Type/Small — 12px / 400
Supporting detail and secondary descriptions.
Card descriptions, captions, tooltips, helper text below inputs, footnotes.
7
Type/Label — 11px / 500 / Uppercase
View Project
Button labels, navigation links, tab labels, form field labels. All interactive text that requires a call to action.
8
Type/Micro — 10px / 500 / Uppercase
UX Design · 2024
Eyebrows, tag labels, style annotation names, timestamp metadata, category chips. Never use for prose.
Do
Follow the hierarchy in order — skip levels intentionally to create contrast (e.g. Heading-1 directly to Body).
Use Label and Micro for all uppercase text — never apply text-transform manually to Body or Small.
Pair Micro with Colour/Text/Tertiary for eyebrows to signal secondary importance.
Don't
Don't use Display outside the hero. Don't use two Display instances on one page.
Don't use Micro for body copy or descriptions — it's too small for comfortable reading.
Don't mix heading levels non-sequentially without purpose — e.g. Heading-1 followed immediately by Heading-3.

Do
Use only tokens from the scale. Never use arbitrary values like 20px or 48px.

Don't
Don't use space-1 or space-2 as section padding — it reads as cramped.
Don't use space-6 or space-7 inside components — they are layout-level tokens only.
04 — Component Usage
Button / Primary
Use for
The single most important action on a view. "View project", "Download CV", "Send message". One primary button per screen section maximum.
Avoid
Multiple primary buttons side-by-side. Destructive or low-priority actions. Navigation that is better served by a text button.
Button / Secondary
Use for
Supporting actions alongside a primary button. "Cancel", "Go back", "View all". Can appear multiple times if actions are equivalent in weight.
Avoid
Using as the sole button when a primary would be clearer. Pairing two secondary buttons where one action is clearly more important.
Button / Text
Use for
Inline navigation and low-emphasis links. "View case study ↗", "See all projects", contextual links inside body text or card footers.
Avoid
Primary or form-submission actions. Anywhere the action needs to be immediately obvious without reading surrounding context.
Tag / Default
Design
Use for
Neutral categorisation and filtering. Skills, disciplines, project categories in their resting/unselected state.
Avoid
Status indicators or anything requiring urgency. Using more than 4–5 tags in a single cluster — use a comma-separated list instead.
Tag / Accent
Featured
Use for
Selected or active filter state. Highlighted categories, "Featured" or "Current" labels. One or two accent tags per view maximum.
Avoid
Applying to every tag — dilutes the emphasis. Using alongside a primary button if both compete for the same accent colour.
Tag / Filled
New
Use for
High-contrast labels that must be noticed first: "New", "Live", "Case Study". Works well over image thumbnails or on dark backgrounds.
Avoid
Generic category labels — the filled weight implies significance. Using more than one or two per screen.
Project Card
UX Design · 2024
Project Title
Short project description.
Use for
Listing portfolio projects in a grid. Each card represents one project. Use eyebrow for discipline and year, Heading-3 for title, Small for description. Always link the entire card.
Avoid
Mixing card sizes in the same grid. Using cards for non-project content like blog posts or testimonials — the visual language implies portfolio work.
Anatomy
Image area — 320×200px placeholder. Replace with project thumbnail, ideally 16:10 ratio.

Eyebrow — Type/Micro, Colour/Text/Tertiary. Format: "Discipline · Year".

Title — Type/Heading-3, Colour/Text/Primary. Keep to one line where possible.

Description — Type/Small, Colour/Text/Tertiary. Max 2 lines.
Hover behaviour
Border transitions from Colour/Border/Default (#ebebeb) to Colour/Text/Tertiary (#8a8a8a). No shadow, no scale transform — keep motion minimal and intentional.
